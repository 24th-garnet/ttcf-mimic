# 工程「帳票」から serve.mjs / doc.mjs / 60-docs.mjs への提案

触ってよいのは app/doc-sales.mjs・app/doc-mfg.mjs だけなので、他のファイルへの変更はここに差分と理由で書く。
どれも差し込み口で足りているので **急ぎではない**。

## 1. doc.mjs `帳票の種類` の 請求書 の 生成元 が実物と違う

実物 334 件の PDF は末尾に「made with documint」の帯がある（例 `販売-売掛台帳-請求書__rec013p12MjRqxC6I__DO032-202404.pdf`）。
Producer が Skia/PDF なのは Documint が Chromium で印刷しているからで、テンプレートの主体は Documint。

```diff
-  { 鍵: "請求書", 名: "請求書", 実物: 334, 生成元: "ヘッドレスChromium（Skia/PDF）", 紙: "A4" },
+  { 鍵: "請求書", 名: "請求書", 実物: 334, 生成元: "Documint（帯「made with documint」。Producer は Skia/PDF）", 紙: "A4 縦" },
```

同じく 原料棚卸表 は Make の webhook（分類.棚卸表作成）が引き金、仕掛品棚卸表 は PrinceXML（既記）、製造表 は「商品ごとの作業標準の JPEG（行から出したものではない）」。

## 2. 60-docs.mjs の一覧が 実物・紙・生成元 を doc.mjs 側の値で出す

`一覧を描く` は `文脈.帳票の種類`（doc.mjs）の `k.実物 / k.紙 / k.生成元` を出し、doc-*.mjs の `帳票` が持つ同名の値を使わない。
doc-*.mjs の方が実物を読んだ上で書いているので、あるならそちらを優先したい。

```diff
-    中 += `<div class=el><div class=elh>${E(k.名)} <span class=tag>現行の実物 ${k.実物}件</span> <span class=tag>${E(k.紙)}</span> <span class=tag>${E(k.生成元)}</span>...
+    const m = d ?? k;
+    中 += `<div class=el><div class=elh>${E(m.名)} <span class=tag>現行の実物 ${m.実物}件</span> <span class=tag>${E(m.紙)}</span> <span class=tag>${E(m.生成元)}</span>...
```

## 3. 60-docs.mjs の `/doc/:種/:鍵` で 組む が投げた例外が 500 の骨で返る

`d.組む` の例外は serve.mjs の try/catch に落ちて「落ちました」になる。帳票は 1 件ずつ見るものなので、
どの帳票のどの鍵で落ちたかを本文に出すと直しやすい（今回 `undefined` を bind して落ちたときに鍵が分からず、別に再現した）。

```diff
-      const h = d ? d.組む(文脈.db, 鍵, 文脈) : 文脈.帳票を出す(種, 鍵);
+      let h; try { h = d ? d.組む(文脈.db, 鍵, 文脈) : 文脈.帳票を出す(種, 鍵); }
+      catch (e) { return 文脈.出す(res, 文脈.骨("帳票エラー", `<h1>${E(種)} ${E(鍵)} を組めません</h1><pre>${E(e.stack ?? e.message)}</pre>`, null), 500); }
```

## 4. 計算器.値 の既定が「式から見た形」であることを 60-docs の契約に一言

`文脈.書き込み.計算器.値(行, fid)` は既定で関連が表示名の配列・選択肢が名前になる（式の評価用）。
帳票のように関連先の行IDが要る側は第3引数 `true`（生の形）で読む必要がある。60-docs.mjs 先頭の契約にその旨を足すと、次に doc-*.mjs を書く人が同じ穴に落ちない。

## 5. 手元に無くて紙が埋まらないもの（DB 側への要望。コードの変更ではない）

| 帳票 | 欠けているもの | どこにあるか |
|---|---|---|
| 請求書 | 請求書番号の連番、入金行の部門名（「入金-営業第二部」） | Documint 側のテンプレート／入金表 tblb17R1koMmzT9t8（0 行） |
| 請求書 | 出庫.ケース数 fldEAkJSVUlWoPV8t（端数フラグで 0 になる行。実物「5 キロ / 0 ケース」） | 在庫明細（販売/入庫）の端数フラグ fldTnOJElYjGk9iQ3 が要求 0 |
| 原料棚卸表・仕掛品棚卸表 | 期首在庫3（前締日時点の残り）が 116/2,178・8/1,794 行にしか無い | 締処理の画面が要求した行だけ。日次断面で埋まる |
| 製造表 | 製造/出庫（使用原材料）が DB に 0 行。控えは 40 生産指示ぶん | 生産指示編集 Form の読み取り（crawl/24-bom.mjs） |
| 出荷明細書・納品書・受領書 | 実物（Google Drive の PDF） | PDF生成指示 のボタン URL の先。取得していない |
